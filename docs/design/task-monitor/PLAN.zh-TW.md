# Quota Pebble 任務監控規劃

日期：2026-11-02

狀態：1.18.0 已實作；已驗證官方 CLI Hook 實際回合。既有桌面聊天的即時來源尚未驗證，詳見 [驗證報告](VERIFICATION.zh-TW.md)。

分支：`codex/task-monitor-plan`，基於 main `4c15a37`（v1.17.0 使用趨勢）。

## 1. 要解決的問題

在查看訂閱配額的同時，知道有哪些 Codex 任務仍在處理、哪些需要使用者確認，以及各任務屬於哪個專案，減少反覆切換 Codex 視窗。

第一版只做唯讀監控，不代送提示詞、不繼續任務、不批准操作、不終止程序、不修改聊天或專案。Claude、Antigravity 任務監控留待後續評估，不能因已有這兩家的配額介面就假定也能取得任務狀態。

## 2. 已確認與尚未確認的邊界

| 項目 | 現況 |
|---|---|
| 本聊天助理 | 在此 Codex 環境獲提供任務清單工具；先前已成功讀取一次任務狀態快照 |
| Quota Pebble | `src/rpc.ts` 自行啟動 stdio app-server；目前 Codex 讀取使用 account/read 與 account/rateLimits/read |
| 官方介面 | 提供 thread/list、thread/loaded/list、thread/status/changed 與 turn 生命週期事件 |
| 跨程序即時狀態 | 尚未證明 Pebble 的獨立 app-server 能觀察桌面 App／其他 CLI 實例的即時狀態 |
| 助理工具可否直接交給 App 用 | 不能假定；助理的工具權限與桌面程式的可用 API 不同 |
| 全部裝置、雲端任務 | 未驗證，不在第一版預設涵蓋範圍 |

官方參考：[Codex App Server](https://developers.openai.com/codex/app-server/)（查閱日期 2026-11-02；目前網址會轉向官方文件站）。協定存在不代表已取得其他實例的讀取權限。實驗結果要記錄安裝版本與來源，不能只依網頁文件宣稱本機版本可用。

重要語意：thread 是一段會話；turn 是其中一輪執行。保存中的會話不代表正在執行。idle 不表示整個工作已完成；notLoaded 不表示從未執行或已完成。active 若伴隨等待旗標，也不能直接計為仍在運算。

## 3. 資料路徑選擇

| 順序 | 路徑 | 採用條件 | 限制 |
|---|---|---|---|
| A | 官方 app-server 唯讀介面 | 本機版本支援；實測能提供目標實例的狀態且不改變會話生命週期 | 獨立程序可能只知道自己的 runtime |
| B | 使用者明確啟用的本機狀態橋接 | A 無法跨實例；有可安裝、可維護且獲授權的來源端整合 | 不能把助理內部工具當成可由外部任意呼叫的服務 |
| C | 本機歷史 metadata | 只能讀到會話標題、目錄與紀錄時間 | 只顯示「歷史紀錄／狀態未知」，不能計入正在執行 |

推薦先驗證 A。若證實隔離，明確回報，改評估 B；若沒有可靠的橋接入口，第一版就只顯示歷史／未知，或保留尚未連接的任務頁，不假裝具備即時監控。

不以 CPU 使用量、codex.exe／node.exe 程序存在、檔案最近修改或 JSONL 最後寫入時間推斷「正在執行」。不直接修改 Codex 資料庫、不掛入或攔截既有 stdio、不開啟不明內部控制埠。

## 4. 畫面與操作

延續黑色圓角、灰色細框、淡紫選取狀態及緊湊排列，保持目前 464px 視窗寬度。沿用第二列的分頁區，增加第三項「任務」。

```text
Quota Pebble v…                   剩餘｜已用｜配速   ⌄

           配額 ｜ 帳號 ｜ 任務

Codex 任務          本機 · 已連接     更新於 16:35:04
已確認執行 2   等待確認 1   未知 3

┌ 修正登入流程                         執行中 ● ┐
│ quota-pebble                         16:35:02 │
│ 來源：本機桌面 App · 即時狀態                  │
└──────────────────────────────────────────────┘
┌ 補上測試                           等待確認 ◐ ┐
│ openmeeting                         16:34:50  │
│ 來源：本機 CLI · 即時狀態                      │
└──────────────────────────────────────────────┘

本機執行       語言  設定          任務同步正常 ●
```

以上名稱與數字均為示意，不是實際查詢結果。任務頁不沿用配額百分比與「剩餘／已用／配速」的語意：頂部切換器在此頁隱藏，但保留原占位，不移動標題、版本與收合按鈕。切回配額時還原原本模式。

- 固定現有三家配額卡片的布局與任務頁彼此獨立，不把任務列塞進每張配額卡。
- 任務列顯示標題、專案短名、狀態、來源、最後確認時間；完整專案路徑可展開唯讀查看。
- 標題缺失時顯示「未命名任務」及短識別碼，不把提示詞原文當標題。
- 預設優先列出等待確認、已確認執行、未知、閒置；同組依最新觀測排序。封存紀錄預設排除，僅能在歷史檢視選擇查看。
- 支援「全部／執行中／等待確認／狀態未知」篩選、搜尋已載入標題與專案；清楚顯示分頁與載入範圍，避免把部分清單當總數。
- 事件更新只更新狀態欄與必要順序，不打斷鍵盤焦點或讓正在查看的列跳動；使用者正在操作時暫緩重排。
- 超過螢幕工作區時內容可捲動，標題與底列保持可達；沿用趨勢功能已驗證的不占寬度捲動方式。
- 第一版不提供任意命令、執行／停止、批准、封存／刪除或寫入功能。「開啟原任務」須先驗證有受支援的連結格式，未驗證則不顯示按鈕。

### 收合島摘要

維持目前寬高及 Claude／Codex／Antigravity 配額區塊位置，不直接多塞一段文字而拉長島。

建議在既有名稱／版本區提供可選的任務摘要模式，例如「Codex 執行 2」，第二行「待確認 1」。與上方寵物共用位置時由使用者選擇「品牌／任務摘要／寵物」，不任意覆蓋既有寵物設定。名稱區的寬度不足時採短文案與完整提示框，不壓縮配額列。

數字只計入已確認且仍新鮮的狀態；資料範圍不完整時顯示「已確認執行 2」，提示涵蓋來源，不使用暗示全域完整清單的總數。連線失效改成「任務狀態未知」，不能顯示 0 或沿用過期數字。

## 5. 狀態模型

| 顯示 | 必要證據 | 是否列入執行數 |
|---|---|---|
| 執行中 | 可信來源的當前 active／turn 執行事件，且沒有等待旗標 | 是 |
| 等待確認 | 明確等待批准、輸入或互動的旗標／事件 | 否，另列等待數 |
| 閒置 | 相同來源的明確 idle 快照，或已終止回合且沒有更新的執行 | 否 |
| 已完成回合 | 某 turn 的成功完成事件，且沒有更新的 turn | 否；不得因此宣稱整個專案或任務目標已完成 |
| 失敗／中斷 | 對應 turn 的 failed／interrupted 狀態 | 否，不當作成功 |
| 狀態未知 | notLoaded、來源不支援 runtime、歷史紀錄、過期或失聯 | 否，另列未知數 |

區分三種時間：來源回報的歷史更新時間、狀態觀測時間、連線健康確認時間。收到舊事件不能刷新成新的觀測；只收到連線心跳也不能把舊 active 當成已重新確認。

每一列至少保存 provider、hostId、instanceId、threadId、turnId（可缺）、title、projectPath、sourceKind、status、waitingFlags、observedAt、sourceUpdatedAt、connectionState 與 coverage。可選的來源序號用於處理亂序；沒有序號時不能用本機到達順序跨 turn 覆蓋新狀態。

以 hostId + instanceId + threadId 為來源識別。跨實例同 threadId 的重複紀錄只有在來源可證明為同一執行時才去重；無法確認時顯示來源分組與不完整範圍，不重複加總，也不把兩個來源各自的狀態硬合併。

## 6. 同步、保存與安全

- 優先採狀態事件與唯讀快照，不執行模型推理，不消耗 token 來「詢問任務在不在跑」。
- 預計可見任務頁每 5 秒做本機健康檢查；其他畫面每 15 秒；只在需要時補齊清單與游標。這些是待效能驗證的初始值，不是正式保證。
- 斷線立即將來源標為失聯，該來源所有執行數失效。若來源支援唯讀對帳，每 30 秒重新確認；超過 45 秒無法取得有效確認則標未知。無法定期確認的來源不得宣稱持續即時。
- 重連使用 1／2／4／8 秒退避，最多 30 秒並加隨機抖動；不連帶增加訂閱配額同步頻率。
- 列表分頁預計每批 50 筆，第一版最多載入 500 筆 metadata，顯示部分載入及繼續載入入口；不靠掃描整份對話維持即時頁。
- 任務事件與配額歷史分開。第一版只保留必要的本機 metadata 快取，退出／重啟後不把快取 active 當即時狀態；確認前一律未知。
- 預設不保存對話、提示詞、工具參數、shell 命令、完整 transcript 或憑證；不讀取 auth.json，不複製 bearer token 作為任務清單整合方式。
- 任務標題、專案路徑及服務回傳全部視為不可信文字；使用 textContent，限制字數，不能解析成指令、HTML 或自動開啟 URL。
- 如採本機橋接，優先有 OS 權限控管的 named pipe／Unix socket；不得無驗證監聽 0.0.0.0。若需 localhost HTTP，使用能力憑證、來源驗證與最小唯讀資料白名單，禁止任意檔案路徑／命令參數。
- Electron renderer 只使用白名單 IPC；不直接存取 Codex 檔案、資料庫或 socket。原有配額功能在任務來源失敗時仍須正常使用。

## 7. 可行性驗證：先於 UI 實作

這一階段是後續實作的第一個工作項；本次規劃尚未執行以下實驗。

1. 盤點目前安裝的桌面 App／CLI 版本、支援協定與傳輸方式，產生版本化、去識別化的能力報告。
2. 只讀查詢 Pebble 獨立實例的 thread/list 與 loaded 清單，檢查分頁、sourceKinds、runtime status。避免預設篩選只涵蓋部分來源卻誤報完整。
3. 用隔離的兩個 app-server A、B，將「同一來源的已知狀態」作為對照，測試 B 能否讀到 A 的即時狀態。不得透過 thread/resume 來讓歷史紀錄看起來變成已載入。
4. 未經新增授權不向正式帳號送測試推理；優先以 fixture 重播事件，再被動對照使用者自然執行中的桌面任務。需要實際開始測試 turn 時，在後續執行階段明確說明其成本與範圍。
5. 比對 active、等待確認、idle、完成、失敗、中斷、關閉來源與重連；記錄不同實例是否一致、事件延遲及缺失的轉換。
6. 查證是否有官方、使用者可啟用的來源端讀取／橋接入口。沒有則明確判定「僅歷史可用」，不碰內部私有控制通道。

交付報告必須包含「看得到什麼／看不到什麼」、支援的實例與裝置範圍、延遲、唯讀性、需要的權限，以及採用 A／B／C 的依據。除這個先決條件外，不讓 UI 完成度掩蓋來源不可用。

## 8. 實作階段與驗收

| 階段 | 工作 | 完成條件 |
|---|---|---|
| P0 | 上述可行性驗證 | 有可重現的能力矩陣與限制，不猜測跨實例狀態 |
| P1 | 來源 adapter、正規化狀態與聚合 | 純單元測試可重播各種來源事件，與配額 Poller 解耦 |
| P2 | 任務分頁與篩選 | 四語系、窄視窗、鍵盤及小螢幕無重疊；原卡片座標不變 |
| P3 | 連線健康、重連與未知降級 | 斷線、資料過期、來源關閉不再顯示舊執行數 |
| P4 | 可選收合摘要 | 固定寬高，不移動供應商區塊；與名稱區寵物設定互斥且可恢復 |
| P5 | 隔離整合驗證與實機截圖 | 任務數與可信對照一致、無額外推理、無任務寫入 |

必測案例：

- 歷史剛更新、程序存在、CPU 忙碌、notLoaded，均不能單獨產生執行數。
- active 與 waitingOnApproval 同時出現時顯示等待；成功完成一輪後，下一輪仍可變回執行，不把會話永久標完成。
- 舊 turn 的完成事件延遲抵達時，不能把新的執行 turn 清掉。
- 同一來源重複事件、跨實例同名任務與同 threadId 不重複計數；未能去重時明示不完整。
- 連線中斷、心跳有但狀態過期、App 重啟與來源重啟，都不能保留過期 active。
- 分頁不完整、不同主機、不同帳號及來源未授權時，不宣稱全域清單。
- 中文／英文／日文／韓文長標題、路徑、無標題、超過 500 筆與篩選空白狀態。
- 原有配額、帳號切換、使用趨勢、寵物及視窗貼邊功能回歸。

## 9. 本次交付與後續

本次只建立規劃分支並保存文件，不修改正式 App、不啟動測試推理、不建立新的使用者聊天、不安裝橋接，也不開放任務控制權限。後續應先執行 P0，依實際證據更新本文件，再決定是否進入產品實作。
